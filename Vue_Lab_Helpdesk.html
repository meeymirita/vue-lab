1. Зачем фреймворк: DOM руками vs декларативно #

Список тикетов с фильтром по статусу. Без фреймворка:

const tickets = [...];                       // данные
let status = 'open';                          // состояние фильтра

function render() {                           // синхронизация данных с DOM — вручную
  const ul = document.querySelector('#list');
  ul.innerHTML = '';
  for (const t of tickets) {
    if (status !== 'all' && t.status !== status) continue;
    const li = document.createElement('li');
    li.textContent = `#${t.id} ${t.title}`;
    li.addEventListener('click', () => open(t.id));
    ul.append(li);
  }
  document.querySelector('#count').textContent = ul.children.length;
}
document.querySelector('#filter').addEventListener('change', e => { status = e.target.value; render(); });
render();

Работает. Проблемы начинаются на второй неделе:

Общий знаменатель: без фреймворка вы поддерживаете два источника правды — данные и DOM — и обязаны вручную держать их в согласии. Vue переворачивает это: вы описываете, как DOM должен выглядеть для данного состояния, а синхронизацию берёт на себя реактивность. Формула: UI = f(state). Всё остальное — детали того, как эта функция устроена и как её разбивать на части.

ГЛАВНАЯ МЫСЛЬ ЛАБЫ

Vue — это три вещи: реактивность (данные знают, кто от них зависит), компоненты (функция от состояния разбивается на переиспользуемые части с явными входами и выходами) и экосистема (Router — состояние адресной строки, Pinia — состояние, общее для компонентов). 2. Азбука Vue — каждое понятие на примере helpdesk #

Четырнадцать понятий, без которых не прочитать ни одного компонента. Каждое — определение и несколько строк. В сессии 1 вы напишете это руками.

2.1 SFC — однофайловый компонент

Файл .vue с тремя секциями: <script setup> (логика), <template> (разметка), <style scoped> (стили только этого компонента). Vite компилирует его в обычный JS.

<script setup>
import { ref } from 'vue'
const count = ref(0)                     // всё, что объявлено здесь, доступно в template
</script>

<template>
  <button @click="count++">Кликов: {{ count }}</button>
</template>

<style scoped>
button { padding: 4px 12px; }            /* не протечёт в другие компоненты */
</style>

2.2 ref и reactive — реактивное состояние

ref(x) оборачивает значение в объект с полем .value; Vue видит чтения и записи .value и знает, кто зависит. В шаблоне .value не пишется — разворачивается автоматически. reactive(obj) делает реактивным объект целиком (через Proxy), без .value. Правило: ref для всего, reactive — для группы связанных полей формы.

const status = ref('open')               // примитив → ref
status.value = 'closed'                  // в скрипте — .value

const filters = reactive({ status: 'open', q: '' })   // объект → reactive
filters.q = 'ошибка'                     // без .value
const { q } = filters                    // ❌ деструктуризация теряет реактивность — q теперь просто строка

2.3 computed — вычисляемое значение

Значение, зависящее от других реактивных данных; пересчитывается только когда они изменились, и кэшируется. Это функция от состояния — не место для побочных эффектов.

const visible = computed(() =>
  tickets.value.filter(t => filters.status === 'all' || t.status === filters.status)
)
// visible.value — массив; пересчёт при изменении tickets или filters.status, и ни при чём другом

2.4 watch и watchEffect — реакция на изменение

watch(source, cb) — «когда это изменится, сделай то»: запрос к API при смене фильтра, синхронизация с URL, логирование. watchEffect(fn) — запускает fn сразу и повторно при изменении всего, что fn прочитала. Для побочных эффектов; для производных значений — computed.

watch(() => filters.status, async (next, prev) => {
  tickets.value = await api.tickets.list({ status: next })      // побочный эффект: сеть
})
watch(filters, save, { deep: true })     // объект целиком: любое вложенное изменение

2.6 Компонент, props и emits — входы и выходы

Компонент — переиспользуемая часть UI с явным контрактом: props — что он принимает (только чтение), emits — какие события посылает наверх. Данные текут вниз, события — вверх (one-way data flow). Ребёнок не меняет props.

<!-- TicketCard.vue -->
<script setup>
const props = defineProps({
  ticket:   { type: Object, required: true },
  selected: { type: Boolean, default: false },
})
const emit = defineEmits(['select', 'status-change'])
</script>

<template>
  <article :class="{ selected }" @click="emit('select', ticket.id)">
    <h3>{{ ticket.title }}</h3>
    <select :value="ticket.status" @change="emit('status-change', ticket.id, $event.target.value)">…</select>
  </article>
</template>

<!-- родитель -->
<TicketCard :ticket="t" :selected="t.id === selectedId" @select="selectedId = $event" @status-change="changeStatus" />

2.7 v-model на компоненте — defineModel

Сахар над парой «prop modelValue + событие update:modelValue». В Vue 3.4+ — defineModel(): компонент получает ref, который синхронизирован с родителем.

<!-- SearchInput.vue -->
<script setup>
const model = defineModel({ type: String, default: '' })
</script>
<template><input :value="model" @input="model = $event.target.value" placeholder="Поиск" /></template>

<!-- родитель -->
<SearchInput v-model="filters.q" />

2.8 Слоты — контент от родителя

Props передают данные, слоты — разметку. Компонент BaseModal не знает, что внутри; родитель кладёт что угодно. Именованные слоты — несколько «дырок»; scoped-слоты — компонент отдаёт данные в разметку родителя.

<!-- BaseModal.vue -->
<template>
  <div class="modal">
    <header><slot name="title">Без названия</slot></header>     <!-- дефолт, если не передали -->
    <slot />                                                   <!-- default-слот -->
    <footer><slot name="actions" :close="close" /></footer>    <!-- scoped: отдаёт close наверх -->
  </div>
</template>

<!-- родитель -->
<BaseModal>
  <template #title>Новый тикет</template>
  <TicketForm @saved="…" />
  <template #actions="{ close }"><button @click="close">Отмена</button></template>
</BaseModal>

2.9 Жизненный цикл

Компонент рождается (setup → монтирование в DOM), живёт (обновления), умирает (размонтирование). Хуки: onMounted — DOM есть, можно мерить, подписываться, фокусировать; onUnmounted — отписаться, остановить таймеры, закрыть сокет. setup сам по себе — «до монтирования». Забытая отписка в onUnmounted — самая частая утечка.

onMounted(() => socket.on('ticket.updated', apply))
onUnmounted(() => socket.off('ticket.updated', apply))

2.10 Composable — переиспользуемая логика

Функция useXxx(), которая внутри использует ref/computed/watch/хуки и возвращает реактивные значения. Это способ вынести логику (загрузка с индикатором, debounce, подписка на сокет) из компонента — как компонент выносит разметку. Composable вызывается в setup, состояние у каждого вызова своё.

export function useAsync(fn) {
  const data = ref(null), error = ref(null), loading = ref(false)
  async function run(...args) {
    loading.value = true; error.value = null
    try { data.value = await fn(...args) } catch (e) { error.value = e } finally { loading.value = false }
  }
  return { data, error, loading, run }
}
// в компоненте:
const { data: ticket, loading, run } = useAsync(id => api.tickets.get(id))

2.11 provide / inject — данные через уровни

Родитель provide('key', value), любой потомок на любой глубине inject('key'). Для «инфраструктурных» вещей: тема, тосты, текущий пользователь в поддереве. Не замена Pinia: без реактивного обёртывания и без единого места изменения.

2.12 Template refs и Teleport

useTemplateRef('name') + ref="name" в шаблоне — доступ к DOM-элементу или экземпляру дочернего компонента (фокус, скролл). <Teleport to="body"> — рендерит содержимое в другое место DOM (модалки, тосты), оставаясь логически внутри компонента.

2.13 Router и Pinia — состояние вне компонентов

Vue Router — адресная строка как состояние: /tickets/42/comments → какой компонент показать и с какими параметрами. Pinia — состояние, которое нужно многим компонентам сразу (текущий пользователь, кэш тикетов, тосты): один store, компоненты читают и зовут actions. Подробно — разделы 5 и 6.

2.14 Options API vs Composition API

// Options API (Vue 2 стиль, работает и в 3)          // Composition API + <script setup> (мы пишем так)
export default {                                       <script setup>
  data() { return { count: 0 } },                      const count = ref(0)
  computed: { double() { return this.count * 2 } },    const double = computed(() => count.value * 2)
  methods: { inc() { this.count++ } },                 function inc() { count.value++ }
  mounted() { … },                                     onMounted(() => { … })
}                                                      </script>

Options группирует по типу (все data, все methods), Composition — по смыслу (всё про фильтр вместе, всё про сокет вместе) и позволяет выносить смысл в composable. В чужом коде встретите оба; в лабе — только Composition.

Понимать это не обязательно, чтобы писать компоненты, — но обязательно, чтобы понимать, почему «оно не обновилось».

🔬 Под капотом: ref — это тоже объект с get/set, и почему в шаблоне .value не нужен

ref(0) возвращает объект { value: 0 } с геттером и сеттером на value, которые делают то же, что ловушки Proxy. Поэтому примитивы тоже отслеживаются — через объект-обёртку. В шаблоне компилятор видит, что count — ref верхнего уровня, и сам подставляет .value. Внутри reactive-объекта вложенные ref тоже разворачиваются: state.count вместо state.count.value. А в массиве — нет: list[0].value. Эти три правила покрывают 95 % «почему тут .value, а тут нет».

Стабильность ключей. v-for с :key="t.id" нужен не «для устранения warning»: по ключу Vue понимает, какой DOM-узел соответствует какому элементу, и при удалении второго тикета из пяти уберёт один узел, а не перерисует четыре. Ключ по индексу ломает это: при удалении элемента все последующие «меняют содержимое», теряя состояние инпутов внутри.

4. Компонентная архитектура #

4.1 Где живёт состояние

Главный вопрос при проектировании. Ответ по возрастанию «радиуса»:

компоненту и его детямref у родителя, вниз через props, вверх через emitsвыбранный тикет в списке + карточки

Ошибка новичка — тащить всё в Pinia («глобально же удобнее»). Состояние с минимальным радиусом проще тестировать и невозможно сломать из другого места.

4.2 Presentational vs container

Презентационные компоненты (TicketCard, BaseModal, StatusBadge) получают всё через props, ничего не знают про API и store, пере­используемы и тестируемы. Контейнеры (страницы, BoardView) знают про store и роутер, загружают данные и раздают их вниз. Хорошее соотношение — много первых, мало вторых.

4.3 Props vs slots

Если родитель хочет передать данные — props. Если разметку (что показать в теле модалки, как выглядит пустое состояние списка) — слот. Компонент с 12 булевыми props типа showTitle, showFooter — кандидат на слоты.

4.4 Контракт компонента

<script setup>
// 1. входы — со схемой: тип, обязательность, дефолт, валидатор
const props = defineProps({

  priority: { type: String, default: 'medium', validator: v => ['low', 'medium', 'high'].includes(v) },

// 3. модель — если компонент «редактирует значение» родителя

Всё, что не в этих четырёх местах, — приватная деталь компонента. Это те же принципы, что в ООП-лабе: явный контракт снаружи, инкапсуляция внутри.

🔬 Под капотом: почему фильтры — в query, а не в ref

Если фильтры списка живут в локальном ref, они пропадают при F5, их нельзя отправить коллеге ссылкой, а кнопка «назад» из тикета возвращает в неотфильтрованный список. Хранить их в route.query решает все три проблемы — но требует двусторонней синхронизации: query → состояние формы при загрузке, состояние → query при изменении (router.replace, чтобы не засорять историю). Это делает composable useRouteQuery в сессии 4 — типичный пример «логика, которую хочется вынести».

Три состояния любой загрузки — loading, error, data — должны быть отражены в UI всегда, не только «когда вспомнили». Composable useAsync (2.10) делает это правило дешёвым. import { Injectable, UnauthorizedException } from '@nestjs/common';
import { users, User } from '../data';

@Injectable()
export class AuthService {
  private tokens = new Map<string, number>();                       // token → userId (игрушечно, в памяти)

  login(email: string, password: string) {
    const user = users.find(u => u.email === email && u.password === password);
    if (!user) throw new UnauthorizedException('Неверный e-mail или пароль');
    const token = `t-${user.id}-${Math.random().toString(36).slice(2)}`;
    this.tokens.set(token, user.id);
    return { token, user: this.publicUser(user) };
  }

  userByToken(token?: string): User | null {
    const id = token ? this.tokens.get(token) : undefined;
    return users.find(u => u.id === id) ?? null;
  }

  publicUser(u: User) { const { password, ...rest } = u; return rest; }
}

import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from '@nestjs/common';
import { AuthService } from './auth.service';

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private auth: AuthService) {}
  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest();
    const token = (req.headers.authorization ?? '').replace(/^Bearer /, '');
    const user = this.auth.userByToken(token);
    if (!user) throw new UnauthorizedException('Требуется вход');
    req.user = user;
    return true;
  }
}

import { Injectable, NotFoundException } from '@nestjs/common';
import { comments, history, sleep, tickets, Ticket, User } from '../data';
import { EventsGateway } from '../events/events.gateway';

@Injectable()
export class TicketsService {
  constructor(private events: EventsGateway) {}

  async list(q: { status?: string; priority?: string; q?: string; page?: string; limit?: string }) {
    await sleep();
    let items = tickets;
    if (q.status && q.status !== 'all') items = items.filter(t => t.status === q.status);
    if (q.priority) items = items.filter(t => t.priority === q.priority);
    if (q.q) { const s = q.q.toLowerCase(); items = items.filter(t => t.title.toLowerCase().includes(s) || t.tags.some(tag => tag.includes(s))); }
    const page = Math.max(1, Number(q.page ?? 1)), limit = Math.min(50, Number(q.limit ?? 20));
    return { items: items.slice((page - 1) * limit, page * limit), total: items.length, page, limit };
  }

  async get(id: number) { await sleep(); return this.find(id); }

  create(dto: Pick<Ticket, 'title' | 'description' | 'priority' | 'tags'>, user: User) {
    const now = new Date().toISOString();
    const ticket: Ticket = { id: Math.max(...tickets.map(t => t.id)) + 1, ...dto, tags: dto.tags ?? [], status: 'open', assigneeId: null, reporter: user.email, createdAt: now, updatedAt: now };
    tickets.push(ticket);
    this.events.ticketUpdated(ticket);
    return ticket;
  }

  async update(id: number, patch: Partial<Pick<Ticket, 'status' | 'priority' | 'assigneeId' | 'title'>>, user: User) {
    await sleep();
    if (patch.status === 'closed' && user.role !== 'admin') throw new NotFoundException('Закрывать тикеты может только admin');   // 404 нарочно грубо; см. вопрос 3.3
    const t = this.find(id);
    for (const [field, to] of Object.entries(patch)) {
      const from = (t as any)[field];
      if (from === to) continue;
      history.push({ id: history.length + 1, ticketId: id, userId: user.id, field, from: String(from ?? ''), to: String(to ?? ''), at: new Date().toISOString() });
      (t as any)[field] = to;
    }
    t.updatedAt = new Date().toISOString();
    this.events.ticketUpdated(t);
    return t;
  }

  comments(id: number) { this.find(id); return comments.filter(c => c.ticketId === id); }
  history(id: number)  { this.find(id); return history.filter(h => h.ticketId === id); }

  addComment(id: number, body: string, user: User) {
    this.find(id);
    const c = { id: comments.length + 1, ticketId: id, authorId: user.id, body, createdAt: new Date().toISOString() };
    comments.push(c);
    return c;
  }

  private find(id: number) { return tickets.find(t => t.id === id) ?? (() => { throw new NotFoundException(`Тикет ${id} не найден`); })(); }
}

<script setup>
import { ref, reactive, computed, watch, nextTick } from 'vue'

// ── 1. ref vs let ────────────────────────────────────────────────────────────
let plain = 0                                  // обычная переменная: Vue про неё не знает
const count = ref(0)                           // реактивная: чтение/запись .value отслеживаются
function incBoth() { plain++; count.value++ }  // шаблон обновит только count

// ── 2. computed: производное значение, кэшируется ────────────────────────────
const double = computed(() => {
  console.log('computed double пересчитан')    // увидите в консоли: только когда count менялся
  return count.value * 2
})

// ── 3. reactive: объект целиком, без .value ───────────────────────────────────
const form = reactive({ title: '', priority: 'medium', urgent: false })
const titleLength = computed(() => form.title.trim().length)
const valid = computed(() => titleLength.value >= 5)

// ── 4. watch: реакция на изменение (побочный эффект) ──────────────────────────
const log = ref([])
watch(() => form.priority, (next, prev) => log.value.unshift(`priority: ${prev} → ${next}`))
watch(form, () => console.log('form изменилась (deep)'), { deep: true })

// ── 5. nextTick: DOM обновляется асинхронно ───────────────────────────────────
const pEl = ref(null)                          // template ref: <p ref="pEl">
async function showBatching() {
  count.value++
  console.log('сразу:', pEl.value.textContent)          // старое значение
  await nextTick()
  console.log('после nextTick:', pEl.value.textContent) // новое
}

// ── 6. потеря реактивности ────────────────────────────────────────────────────
const { priority } = form                      // ❌ это просто строка 'medium'; менять form.priority она не будет
</script>

// web/src/api/http.js
export class ApiError extends Error {
  constructor(status, message, body) { super(message); this.status = status; this.body = body }
}

let token = null
export function setToken(t) { token = t }                           // сессия 3 будет вызывать из auth-store

export async function http(method, path, body) {
  const res = await fetch(`/api${path}`, {
    method,
    headers: { 'Content-Type': 'application/json', ...(token ? { Authorization: `Bearer ${token}` } : {}) },
    body: body === undefined ? undefined : JSON.stringify(body),
  })
  const data = res.status === 204 ? null : await res.json().catch(() => null)
  if (!res.ok) throw new ApiError(res.status, data?.message ?? res.statusText, data)
  return data
}

// web/src/composables/useAsync.js
import { ref } from 'vue'

/** Оборачивает async-функцию в три состояния. Каждый вызов useAsync — своё состояние. */
export function useAsync(fn) {
  const data = ref(null)
  const error = ref(null)
  const loading = ref(false)

  async function run(...args) {
    loading.value = true
    error.value = null
    try {
      data.value = await fn(...args)
      return data.value
    } catch (e) {
      error.value = e
      throw e
    } finally {
      loading.value = false
    }
  }

  return { data, error, loading, run }
}

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ

При смене статуса в селекте — «загрузка…» на 300 мс, потом список с сервера. При остановленном API — сообщение об ошибке и рабочая кнопка «повторить». Devtools → Components → PlaygroundView показывает page, error, loading как реактивные значения.

Зачем: Слои (раздел 7): компонент не знает URL, ticketsApi не знает про заголовки и ошибки, http не знает про тикеты. Composable: useAsync — первая вынесенная логика; через сессию у вас будет пять таких. Заметьте data: page — переименование при деструктуризации, потому что useAsync возвращает обобщённые имена. watch(..., { immediate: true }) — идиома «загрузить сразу и перезагружать при изменении» вместо onMounted(load) + отдельного watch.
🔬 Под капотом: почему useAsync и бросает, и сохраняет ошибку

error.value = e — чтобы шаблон показал сообщение. throw e — чтобы вызывающий код (например, форма) мог отреагировать по-своему: не закрывать модалку, откатить оптимистичное изменение. Если бы composable глотал ошибку, форма узнавала бы о ней только через watch(error) — неудобно. Если бы только бросал — каждому компоненту пришлось бы ловить и класть в свой ref. Делает обе вещи — стандартная форма для таких хелперов.

URLSearchParams с фильтром пустых значений — чтобы ?q=&status=all не улетало на сервер. Мелочь, но именно такие мелочи живут в API-слое, а не в компонентах.

Тот же список, но из трёх компонентов. Клик по карточке — выделение (state у контейнера, вниз — prop selected, вверх — событие select). Шаг 2.2defineModel: BaseInput, BaseSelect, FilterBar; useDebounce и серверный поиск#

// web/src/composables/useDebounce.js
import { ref, watch } from 'vue'

/** Возвращает ref, который повторяет source с задержкой. */
export function useDebounce(source, ms = 300) {
  const debounced = ref(source.value)
  let timer
  watch(source, v => {
    clearTimeout(timer)
    timer = setTimeout(() => { debounced.value = v }, ms)
  })
  return debounced
}

// web/src/composables/useNow.js
import { ref, onMounted, onUnmounted } from 'vue'

/** Реактивное «сейчас», обновляется раз в interval мс, пока компонент жив. */
export function useNow(interval = 30_000) {
  const now = ref(Date.now())
  let timer
  onMounted(() => { timer = setInterval(() => { now.value = Date.now() }, interval) })   // хуки внутри composable —
  onUnmounted(() => clearInterval(timer))                                                //  привязаны к компоненту, который его вызвал
  return now
}

Шаг 3.1ticketsStore: state, getters, actions, storeToRefs, защита от гонки#

Список тикетов скоро понадобится трём страницам (список, канбан, деталь) и WebSocket-обработчику. Значит, радиус состояния — всё приложение → store.

// web/src/stores/tickets.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { ticketsApi } from '@/api/tickets'

export const useTicketsStore = defineStore('tickets', () => {
  // ── state ──
  const items   = ref([])
  const total   = ref(0)
  const loading = ref(false)
  const error   = ref(null)

  // ── getters ──
  const byId   = computed(() => Object.fromEntries(items.value.map(t => [t.id, t])))
  const byStatus = computed(() => {
    const groups = { open: [], in_progress: [], resolved: [], closed: [] }
    for (const t of items.value) groups[t.status]?.push(t)
    return groups
  })

  // ── actions ──
  let requestNo = 0                                     // защита от гонки (вопрос 1.5)
  async function load(params = {}) {
    const no = ++requestNo
    loading.value = true; error.value = null
    try {
      const page = await ticketsApi.list({ limit: 50, ...params })
      if (no !== requestNo) return                       // пришёл устаревший ответ — игнорируем
      items.value = page.items; total.value = page.total
    } catch (e) {
      if (no === requestNo) error.value = e
    } finally {
      if (no === requestNo) loading.value = false
    }
  }

  async function fetchOne(id) {
    const t = await ticketsApi.get(id)
    upsert(t)
    return t
  }

  function upsert(ticket) {
    const i = items.value.findIndex(t => t.id === ticket.id)
    i === -1 ? items.value.push(ticket) : items.value.splice(i, 1, ticket)
  }

  return { items, total, loading, error, byId, byStatus, load, fetchOne, upsert }
})

export function persistPlugin({ store, options }) {
  const keys = options.persist                                  // defineStore('auth', fn, { persist: ['token', 'user'] })

  })
}

// router/index.js — глобальный guard; вынесен в функцию, чтобы в тестах ставить его на свой router
import { useAuthStore } from '@/stores/auth'

export function installGuards(router) {
  router.beforeEach(to => {
    const auth = useAuthStore()                    // store доступен здесь — pinia уже установлена в main.js до первой навигации
    if (to.meta.requiresAuth && !auth.isAuthenticated) {
      return { name: 'login', query: { redirect: to.fullPath } }   // вернуть объект = перенаправить
    }
    if (to.meta.requiresRole && auth.user?.role !== to.meta.requiresRole) {
      return { name: 'tickets' }
    }
    if (to.meta.guest && auth.isAuthenticated) {
      return { name: 'tickets' }                                  // залогиненному на /login нечего делать
    }
    // ничего не вернуть = пропустить
  })
}

Все три сценария. Guard — одно место для всех правил доступа; страницы о них не знают. Подсказка на будущее: в проде guard проверяет только наличие токена, а настоящую проверку делает API (401/403) — фронтенд-guard это удобство, не безопасность.

Зачем: beforeEach — перехват любой навигации до рендера. Возврат маршрута = редирект, false = отмена, ничего = пропуск. meta — декларативные правила у маршрута вместо if в каждой странице. Store в guard: вот зачем Pinia была раньше роутера — useAuthStore() вызывается вне компонента, и это работает, потому что app.use(pinia) уже произошёл.

Шаг 4.4useRouteQuery: фильтры в URL через writable computed#

Фильтры списка — в URL: /tickets?status=open&q=vpn. Синхронизация в обе стороны, вынесенная в composable.

// web/src/composables/useRouteQuery.js
import { computed } from 'vue'
import { useRoute, useRouter } from 'vue-router'

/** Реактивный объект, чьи поля читаются из route.query и пишутся в него (replace, чтобы не засорять историю). */
export function useRouteQuery(defaults) {
  const route = useRoute(), router = useRouter()
  const query = {}
  for (const key of Object.keys(defaults)) {
    query[key] = computed({
      get: () => route.query[key] ?? defaults[key],
      set: v => router.replace({ query: { ...route.query, [key]: v === defaults[key] || v === '' ? undefined : v } }),   // дефолт → убрать из URL
    })
  }
  return query
}

import { ref, onMounted, onUnmounted } from 'vue'
import { io } from 'socket.io-client'

/** Подписка на события сокета на время жизни компонента. handlers: { 'event': fn } */
export function useSocket(handlers) {
  const connected = ref(false)
  let socket

  onMounted(() => {
    socket = io({ path: '/socket.io' })                          // тот же origin → через Vite proxy (ws: true)
    socket.on('connect',    () => { connected.value = true })
    socket.on('disconnect', () => { connected.value = false })
    for (const [event, fn] of Object.entries(handlers)) socket.on(event, fn)
  })
  onUnmounted(() => socket?.disconnect())                        // ❗ одна подписка на всё приложение — и одна отписка

  return { connected }
}

🔬 Под капотом: гонка WebSocket vs оптимистичное обновление (вопрос 3.3)

Решение — откатывать не весь объект, а только поле; или updatedAt-сравнение в upsert (не применять версию старше текущей). Реализуйте второе — это 3 строки.

11. Глоссарий #

Реактивность — механизм, при котором чтение данных регистрирует зависимость, а запись — перезапускает зависимые вычисления и обновляет DOM.
SFC (Single-File Component) — файл .vue с секциями script, template, style.
ref — реактивная обёртка над значением с полем .value; в шаблоне разворачивается сама.
reactive — реактивный Proxy над объектом; без .value; деструктуризация теряет реактивность.
computed — кэшируемое производное значение; writable computed имеет и set.
watch / watchEffect — реакция на изменение источника / автоматически отслеживаемых зависимостей; для побочных эффектов.
nextTick — промис, который резолвится после ближайшего обновления DOM.
Директива — атрибут с префиксом v-, управляющий рендером: v-if, v-for, v-model, v-bind (:), v-on (@).
key — стабильный идентификатор элемента в v-for; по нему Vue сопоставляет DOM-узлы и анимирует перестановки.
Props — входные данные компонента, только для чтения; объявляются с типом, обязательностью, дефолтом, валидатором.
Emits — события, которые компонент посылает родителю; объявляются в defineEmits.
One-way data flow — данные вниз через props, изменения вверх через события; ребёнок не мутирует props.
defineModel — двусторонняя привязка на компоненте: prop + событие обновления в одном ref.
Слот — место в шаблоне компонента, куда родитель вставляет свою разметку; именованный, scoped (с данными от компонента), с дефолтом.
$attrs — атрибуты, переданные компоненту, но не объявленные как props; ложатся на корень или туда, куда привязаны через v-bind="$attrs".
Teleport — встроенный компонент, рендерящий содержимое в другой узел DOM.
Жизненный цикл — setup → onMounted → обновления → onUnmounted; в composable хуки привязываются к вызвавшему компоненту.
Template ref — ссылка на DOM-элемент или дочерний компонент: ref="x" + useTemplateRef('x').
Composable — функция useXxx(), инкапсулирующая реактивную логику и lifecycle; вызывается в setup.
provide / inject — передача значения всем потомкам поддерева без props.
Презентационный компонент — получает всё через props, ничего не знает об API и store.
Контейнер (view) — компонент страницы: знает store и роутер, загружает данные, раздаёт вниз.
Store (Pinia) — глобальный реактивный объект: state, getters (computed), actions; один экземпляр на приложение.
storeToRefs — деструктуризация store с сохранением реактивности state и getters.
Оптимистичное обновление — показать результат до ответа сервера, откатить при ошибке.
Pinia plugin — функция, расширяющая каждый store ($patch, $subscribe).
Route / params / query / meta — запись маршрута: путь → компонент; динамические сегменты; необязательные параметры; произвольные метаданные для guard'ов.
Nested routes — дочерние маршруты, рендерящиеся во вложенном RouterView.
Navigation guard — хук до/после навигации: разрешить, отменить, перенаправить.
Lazy loading — компонент маршрута как () => import(...) — отдельный чанк.
History mode — обычные URL без #; сервер должен отдавать index.html на любой путь.
API-слой — модули, знающие URL и формат ответов; единственное место с fetch.
TransitionGroup — анимация появления/исчезания/перемещения элементов списка по key.
Динамический компонент — <component :is="X"> — выбор компонента в рантайме.
defineAsyncComponent — компонент, загружаемый отдельным чанком при первом рендере.
Vue Test Utils — библиотека для монтирования компонентов в тестах: mount, find, setValue, emitted.
